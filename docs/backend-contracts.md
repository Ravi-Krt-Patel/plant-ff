# Proposed separate-backend contracts

These endpoint names and policies are proposals. None are executable local routes.

Every endpoint should return a validated JSON envelope `{ data, requestId }` or `{ error: { code, message, fieldErrors?, retryable }, requestId }`. IDs are opaque strings; currency is INR and all money is integer paise; timestamps are ISO 8601 UTC and display in Asia/Kolkata. Clients pass AbortSignal to cancel requests and ignore obsolete responses. Pagination uses a bounded page size and opaque cursor. Agree session credentials, CORS and CSRF requirements before integration; no credentials belong in browser storage.

| Consumer        | Proposed endpoint                          | Input / output                                                                                       | Notes                                                                                                 |
| --------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Catalog         | GET /v1/products                           | Filters/category/sort/cursor → Product page, nextCursor                                              | Public immutable DTOs, bounded limits, validation and unavailable errors                              |
| Product         | GET /v1/products/[slug]                    | slug → Product with SKU variants, stock, media and care                                              | Public; not_found, unavailable                                                                        |
| Search          | GET /v1/search                             | q/filter/cursor → result page                                                                        | Abort previous request; reject stale results                                                          |
| Serviceability  | POST /v1/serviceability/check              | PIN/address summary → eligible, reason, COD, charges, slots                                          | Syntax is not eligibility; business-approved rules                                                    |
| Quote           | POST /v1/checkout/quotes                   | SKU quantities, address, slot, coupon → versioned quote and expiresAt                                | Trusted line totals, taxes, discounts, shipping; stock/price/slot conflicts                           |
| Order           | POST /v1/orders                            | quoteId/version + contact/address/slot → Order                                                       | Sole commerce-order creator; idempotency key required; quote_expired, stock_changed, slot_unavailable |
| Payment session | POST /v1/orders/[id]/payment-sessions      | existing orderId, method, attempt key → opaque provider handoff                                      | Never creates a second commerce order; backend owns provider sessions/secrets                         |
| Payment status  | GET /v1/orders/[id]/payment-status         | orderId → pending/success/failure plus version                                                       | Only trusted backend confirmation can produce paid UI                                                 |
| Order history   | GET /v1/orders                             | cursor → owned order page                                                                            | Authenticated session required                                                                        |
| Order detail    | GET /v1/orders/[id]                        | orderId → owned order                                                                                | Secure guest access or customer session; forbidden/not_found                                          |
| Tracking        | GET /v1/orders/[id]/tracking               | orderId → fulfillment, recordedAt, receivedAt, sequence, optional synthetic/live coordinate metadata | Ownership required; backend source, stale handling, abort on unmount                                  |
| Cancellation    | POST /v1/orders/[id]/cancellation-requests | reason, idempotency key → request/result                                                             | Server enforces policy, eligibility and refund workflow                                               |
| Addresses       | GET/POST/PATCH/DELETE /v1/addresses        | validated address DTO → owned address(es)                                                            | Auth required, idempotent writes/deletes and field errors                                             |
| Account         | Session/sign-in/sign-out endpoints TBD     | agreed challenge/session flow → customer view                                                        | Backend owns identity, OTP/session issuance, CSRF and authorization                                   |

Zod schemas must validate responses at the eventual HTTP adapter. Map validation, unauthorized, access_denied, not_found, conflict, rate_limited and unavailable errors into recoverable UI states. Retry only safe/idempotent operations. Backend must enforce order ownership, pricing, inventory/resource reservations, real payment verification/webhooks/capture/reconciliation/refunds and durable persistence. No real credentials or financial processing are part of this repository.
